# SCSS

この文書はリニューアル後の実装に適用する。
配置と既存コードからの移行範囲は [ディレクトリ構成](../directory-structure.md) に従う。

## 層

`src/styles/main.scss` で次の順に読み込む。
1ファイル1 Block とし、ファイル名は `_{Block名}.scss` にする。
page 層は1ページ1ファイル（`_p-{ページ名}.scss`）とし、そのページの Block をまとめる。
追加したら `main.scss` の該当層に `@use` を足す。

| 層         | 内容                                 | 接頭辞 |
| ---------- | ------------------------------------ | ------ |
| `function` | CSS を出力しない Sass function       | なし   |
| `mixin`    | CSS を出力しない Sass mixin          | なし   |
| `reset`    | 既定スタイルの打ち消し               | なし   |
| `base`     | デザイントークンと要素の基本スタイル | なし   |
| `layout`   | ヘッダー、フッター、コンテナ、縦積み | `l-`   |
| `module`   | 再利用する部品                       | `m-`   |
| `page`     | 特定ページだけのスタイル             | `p-`   |
| `utility`  | 単機能の補助クラス                   | `u-`   |

各パーシャルは、必要な function と mixin を `@use` で読み込む。
要素セレクターは reset と base 層でのみ、`!important` は utility 層でのみ使う。

## セレクター

- コンポーネントとページ固有の CSS は BEM に従い、Block、Element、Modifier のクラスで指定する。
- 要素セレクター、ID セレクター、ユニバーサルセレクター、位置依存の疑似クラスを使わない。
- 属性に合わせて見た目を変えるときは、BEM クラスの中に `&[target='_blank']` のようにネストする。
  属性セレクターだけで指定しない。
- HTML の構造や要素の並び順に依存するセレクターを避ける。
  スタイルが必要な要素に役割を表す BEM クラスを付ける。
- 状態は `block--modifier` または `block__element--modifier` で表す。
- `:hover`、`:focus-visible`、`:open` などの状態と、`::before`、`::after`、`::backdrop` などの疑似要素は、元セレクター内へ `&` でネストする。
- 同じ要素の複数状態は、`&:hover, &:focus-visible` のようにまとめる。
- 同じ要素に付くライブラリの状態クラスも `&.swiper-button-disabled` のようにネストする。
  その状態の疑似クラスは、さらに内側にネストする。
- 親 Block の状態で Element を変える場合は、Element の元セレクター内に `.block--ready &` のように書く。
- `--ready`、`--active`、`--loading` などの状態を、トップレベルの子孫セレクターに分離しない。

```scss
.m-button {
  color: var(--color-primary);

  &:hover,
  &:focus-visible {
    @include mq(hover) {
      color: var(--color-primary-hover);
    }
  }

  &__icon {
    opacity: 0.6;

    .m-button--ready & {
      opacity: 1;
    }
  }

  @include mq(pc) {
    padding-right: rem(32);
    padding-left: rem(32);
  }
}
```

上の例の `mq(pc)` と `mq(hover)` は、リニューアル時に共通 mixin へ定義してから使う。
現行コードの変更では、`src/styles/tools/_media.scss` に定義済みの名前を使う。

## 値と共通処理

- 横書きのサイトとして、`width`、`height`、`margin-top`、`padding-left`、`border-bottom` などの物理プロパティで書く。
- `block-size`、`inline-size`、`margin-block`、`padding-inline`、`border-block-end` などの論理プロパティは使わない。
- `font-size` は `rem()` で指定し、`px` と `rem` を直接書かない。
- 余白、幅、高さなどの長さも `rem()` を基本にする。
  枠線、影、アウトラインなど、文字サイズに合わせて拡大する必要のない値は `px` で書いてよい。
- `rem()` に渡す px 相当値は整数にする。
  既存値を調整する場合は、最も近い整数に丸める。
- 小数は、透明度、単位なしの行間、比率、`fr`、`em` による字間、秒数、イージング、transform、シェーダー計算など、小数に意味がある値に限る。
- 色、余白、タイポグラフィは `base/_tokens.scss` のカスタムプロパティを使う。
  1箇所でしか使わない例外的な色は直接書いてよい。
- 共通化できる値変換と定型宣言は、既存の function または mixin を使う。
- 共通処理を追加するときは、用途と責務を確認する。
  `function/` または `mixin/` に1ファイル1つで置き、`_index.scss` に `@forward` を足す。
- コメントは基本書かない。
  処理の理由や、コードだけでは分かりにくいことに限る。
  見た目の説明や Figma との比較は書かない。

## ページの Block

`p-{ページ名}` はページを表す接頭辞で、Block にはしない。
ページの部分ごとに `p-{ページ名}-{名前}` の Block を作り、その中を Element で組む。

```scss
.p-home-profile {
  display: flex;

  &__heading {
    color: var(--color-text);
  }
}

.p-work-overview {
  &__item {
    border-top: 1px solid var(--color-border);
  }
}
```

- `p-home__profile` のように、`p-{ページ名}` に直接 Element を付けない。
- Element は、その Block を付けた要素の中に置く。
- Element を持たない部分も、1つの Block にする。

## 文字スタイル

見出しや本文など、繰り返し使う文字の組み合わせは `text-style()` mixin にまとめる。
文字サイズ、太さ、行間、PC での切り替えをまとめて管理する。
具体的な名前と数値は、新しいデザインに合わせて定義してから使う。

HTML の見出しレベルは文書構造で選び、見た目の段階とは分ける。
字間を変えるときは、文字を含む要素に直接指定する。

## Flex と Grid

- 並べる、積むという配置には Flex を使う（ナビゲーション、ボタンの中身、縦積みなど）。
- 決まった列数で同じ幅に並べる場合や、行をまたいで位置を揃える場合は Grid を使う。
- レイアウトを含む部品を提案するときは、Flex と Grid のどちらを使うか、理由と一緒に示す。
- 子要素を一定間隔で縦に積むだけの配置は、共通の `l-stack` にまとめる。
  間隔の種類と Modifier は、実際の用途を確認してから定義する。
- 揃え方や子要素ごとの調整が必要なときは Element を作る。

## position

- テキストとレイアウトは、Flex、Grid、gap、margin、padding などで通常の文書の流れの中に組む。
- 背景、飾り、ツールチップなど本文の流れとは別に置くものと、通常の流れでは再現が難しい配置には `absolute` と `fixed` を使ってよい。
- 要素を重ねるだけなら、Grid のセル重ね（`grid-area: 1 / 1`）も検討する。
- 基準を作る `relative` と、スクロールに追従する `sticky` は制限しない。

## レスポンシブ

- スマートフォンを基準に書き、PC の差分を共通の `mq()` mixin に定義した条件で指定する。
- `@media` を直接書かない。
  条件の名前と切り替え幅は、共通 mixin に集約する。
- `mq()` は対象の BEM セレクター内にネストする。
  ファイル末尾やトップレベルにまとめない。
- 同じ条件を複数のセレクターへ適用する場合も、それぞれの元セレクター内に書く。
- 状態や疑似要素だけに適用する `mq()` は、対応する `&` ブロック内に書く。
- 対応する単一の元セレクターを持たないグローバルな `::selection` は、ネストの例外とする。
- ホバー、視差効果を減らす設定、強制カラーモードなども、共通 mixin の定義済みの条件を使う。

## Lint の例外

BEM、単位、整数値、メディアクエリの規則を無効化しない。
必要な例外は、該当するファイルの範囲に限定し、理由をこの文書と Stylelint 設定に記載する。

リニューアル時の層に伴う例外は、次の範囲に限る。
設定の移植は、別途ユーザーの確認を得てから行う。

| 対象                | 例外                                   | 理由                                     |
| ------------------- | -------------------------------------- | ---------------------------------------- |
| `mixin/`            | `@media` の使用                        | `mq()` 自体の定義に必要なため            |
| `mixin/`            | mixin 定義内のネスト検査               | 呼び出し側のセレクター内で展開されるため |
| `reset/` と `base/` | 要素セレクターとユニバーサルセレクター | 要素の既定スタイルを整えるため           |
| `utility/`          | `!important`                           | 単機能の補助クラスを優先して適用するため |
